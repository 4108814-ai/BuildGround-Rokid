Three properties, and everything else follows

All three were validated on real hardware before a single plugin was written. They are the reason you never touch the glasses.

01

Wake-on-message

A plugin does not need to be running to receive traffic. The hub binds it awake when something arrives for it — a message, a track change, a departure — and it goes quiet again after.

02

One hub-owned link

A single hub-owned session over the Rokid link, with a binary fallback underneath it. No more apps fighting over the connection, and no plugin ever has to know which path its bytes took.

03

Declarative surfaces

Plugins push descriptions of content — a card, a band, a list, an image. The glasses hub renders them locally, in the HUD's one green. Zero glasses-side deployment, forever.

Every tier of the display, shipped

Nothing on the HUD is improvised. Each piece of content declares which tier it belongs to, and the platform — not the plugin — decides how loudly it may speak.

  • AmbientSilent updates. Lyrics advancing, a glanceable refreshing.
  • PinA persistent corner that survives across native screens.
  • ActivityAn ongoing process holding a stable corner, expandable into a panel with real actions.
  • NoticeA band over whatever is underneath. Sixteen structured lines, paged on the glasses, one answer taken.
  • SurfaceThe full thing: cards, timed lines, media decks, list rows, real photographs.

Eight plugins, none of them built in

Every one is an ordinary phone APK installed from the in-app Store, backed by a public registry with SHA-256 and signer pinning checked before the install runs. The hub itself ships empty.

Relay

A message you can answer arrives as a band over whatever you were already looking at, lights the display if it was dark, and is answered out loud. Let one go and it waits in Messages, newest first.

Lens

The glasses camera streams to the phone, where OCR and translation run offline; the overlays come back in real time. Freeze mode captures a full-resolution still through the same link.

Feeds

Bluesky and X timelines — posts, threads, and the actual photos full-screen.

Transit

Nearby stops and live departures, with the ones you actually take kept on top.

Media Deck

Now playing with album art and transport, from whatever app is playing.

Lyrics

Time-synced lines for whatever is playing, pulled from four sources.

Photos Sync

Not a HUD plugin. It copies the photos and videos you shoot on the glasses into your phone gallery by itself, and hands you the switches for it.

Sample

The minimal copyable plugin. Clone it, change the id, and you have a working glasses app that never runs on the glasses.

Installation alone grants nothing. Surfaces, microphone, camera, and HTTP proxy are approved one by one, per plugin, keyed to its package, its plugin id, and its signing certificate.

A phone is all you need

No cable. No PC. No ADB, at any point — including the privileged parts, which the glasses arm by themselves in two cards.

Roadmap

No dates. Items are ordered by the problem they solve, and nothing is listed as shipped until it has run on real hardware.

Shipped

The beta gate is behind us: a stranger sets up Nexus with nothing but a phone.

  • The bus and its trust boundary

    Per-plugin capabilities keyed to package, plugin id, and signing certificate, enforced at the hub.

  • Setup without a computer

    Seven steps on the phone, then a two-card self-arm on the glasses. No ADB, no cable.

  • The distribution loop, closed

    SDK on JitPack, plugins ingested by a public registry, installs verified by hash and signer, everything self-updating.

  • The whole display model

    Ambient, pin, activity, notice, surface — plus HUD motion, a shared glyph set, and plugin marks that travel to the glasses.

  • The camera capability

    Live H.264 over Wi-Fi Direct, decoded on the phone — and the roles invert when the phone's Wi-Fi is off, so it works anyway.

  • Bands that can wake a dark display

    At most one pulse every five seconds across every plugin, always brief, never held on.

Building

Specified and underway.

  • Display arbitration

    The protocol has carried an actionable class since v1, and v1 still renders it as a toast. This is the first problem two chatty plugins will create.

  • Continuous speech

    Speech-to-text ships in short takes. The remaining slice is the continuous mode that live captions and a voice assistant are both blocked behind.

Next

Committed, not started.

  • Native apps in the menu

    List and launch real glasses APKs from the same triple-tap menu. Nexus does not port them; it stops you having to leave.

  • A nav surface kind

    Turn-by-turn deserves a real surface. Navigation degrades to a text card until it exists.

  • Maven Central

    JitPack carries the SDK today. Central once the AIDL surface is stable — a published coordinate is what makes a platform safe to bet on.

Exploring

Not committed. Each one is an ordinary phone APK against a capability that already exists.

And what stays off it

Native glasses apps are launched from the menu, never absorbed into it. Plugin code stays on the phone — the glasses half of any capability lives in the hub, which is exactly what makes zero glasses-side deployment possible. And there is no signature-only plugin permission, because no third-party developer can be signed with our key.

Write one yourself

A plugin is a headless phone APK against the published SDK. No glasses code, no emulator, no device flashing — you describe what should appear, and the glasses draw it.

  • The plugin contract complete and self-contained
  • SDK reference surfaces, lifecycle, design kit
  • The sample plugin the canonical template
  • Publish to the registry F-Droid-like: you host, we index
build.gradle.kts
repositories { maven("https://jitpack.io") }

dependencies {
    implementation(
        "com.github.Anezium.Rokid-Nexus:bus-client:sdk-v0.9.0"
    )
}

Your plugin declares an id, a mark, and the capabilities it needs. The user grants them. The hub enforces them.
